# UX Spec — StreakKeeper (MVP slice)

> Owner: UI Designer Agent · Status: ready for Architect · Source: `03-ux.md`

## Scope note

This slice ships as a headless service — there is no frontend yet, and no existing component library to extend (greenfield: everything named below is new). Layout is described in prose, as intent for whichever frontend eventually renders it; the *copy* is the binding deliverable, since these strings are exactly what "mirror, not scoreboard" sounds like in practice and may seed the service's own returned messages. Per `03-ux.md`'s data-contract note, the service itself returns raw booleans/integers/dates, never these strings directly — but they're written to be dropped in wherever a frontend needs user-facing text for a given state.

Four states recur per habit, derived directly from `03-ux.md`'s resolved semantics: **not started** (`currentStreak: 0`, never logged), **healthy** (already logged today), **at-risk** (`atRisk: true`), and **broken** (`currentStreak: 0` after a gap, `longestStreak` > 0). Everything below is organized around these four, plus the list-level empty/loading/error states.

## 1. Layout & visual hierarchy

**Habit list.** One row per habit, read left to right in this order: habit name first (plain text, medium weight — this is the row's identity, not a rank), then the current-streak figure, then — only when relevant — a state tag sitting immediately beside it, then the longest-streak figure in smaller/muted type, then the log-today control anchored to the row's end. The current-streak number is the largest figure in the row, but stays at a modest, body-adjacent type size — never hero/display scale, never color-filled, never icon-wrapped. Nothing in the row should let one habit visually outrank another (no per-row color grading, no size scaling by streak length): every row carries the same weight, because the product's own non-goals rule out any cross-habit comparison, even implicit.

**Habit detail** (however the future frontend navigates there — route, modal, or expansion; this spec doesn't prescribe the mechanism). Habit name as the page heading. Directly beneath it, the current-streak figure gets the most visual weight anywhere in this spec — the one place it's allowed real size — because the user arrived specifically to check this habit, so the hierarchy earns it. It's still typographically plain: a numeral plus a unit word plus a small label above or below ("Current streak"), no gradient, no trophy iconography, no flame. The state tag (at-risk or broken), when present, sits directly below or beside that number as a separate line — never overlaid on the number itself, never replacing it. Longest streak follows underneath, at roughly two-thirds the current-streak's type size, its own small label ("Longest streak") always present. A last-logged date, when one exists, sits as a small factual line near the longest-streak figure. The log-today control anchors the bottom of the block.

**The longest-streak figure is always visible, in every state, including "not started" (where it reads 0) — never something that only appears after a break.** Making it conditional would turn it into a consolation prize shown only once things go wrong, which undercuts the "it's just information" stance; showing it constantly makes clear it was never hidden.

## 2. All states — layout + final copy

### Not started
*Habit exists, zero logs. `currentStreak: 0`, `longestStreak: 0`, `atRisk: false`.*

**Layout.** Same row/detail structure as any habit — no dimmed styling, no "inactive" treatment, no state tag. The 0 renders in the exact same weight and color as any other current-streak number; only the caption underneath distinguishes it from broken, since the two share the same digit.

**Copy.**
> Not started yet. Log today to begin.

### Healthy (logged today)
*`currentStreak` ≥ 1, `atRisk: false`, already logged today — covers both a fresh first-day streak and an ongoing one.*

**Layout.** Default resting treatment: no tag, no badge, no highlight ring. The log-today control shows its completed variant (label swaps to "Logged," not removed or hidden — see §4 on why nothing disappears).

**Copy** (this line doubles as the confirmation shown immediately after logging — see §4):
> Logged today.

### At-risk
*Completed yesterday, not yet today. `currentStreak` holds yesterday's intact count; `atRisk: true`.*

**Layout.** The current-streak number is unchanged from yesterday — rendered exactly as it would be on any healthy day, at the same size and weight. The state tag sits beside/below it as plain text in the row's normal ink color (not red, not orange, not a saturated accent) — it should look like any other metadata label, not an alert.

**Copy** — compact tag (list row):
> Not yet today

**Copy** — full line (detail view):
> Logged yesterday. Not yet today.

### Broken
*Gap ≥ 1 day since last completion. `currentStreak: 0`, `longestStreak` unchanged and shown, `atRisk: false`.*

**Layout.** The current-streak 0 renders in the same plain weight as "not started." The only differentiators from "not started" are the state tag and the fact that longest streak reads > 0 — that pairing (a 0 next to a nonzero longest, plus the tag) is what tells the story; no sentence has to assert "your history wasn't erased" because the persistent longest-streak number demonstrates it structurally. The word "broken" itself never appears in any user-facing string — it's a data-model label, not copy.

**Copy** — compact tag (list row):
> New streak

**Copy** — full line (detail view):
> Not logged yesterday. Today starts a new streak.

### Empty (no habits yet)
*Fresh instance, no habits configured.*

**Layout.** Replaces the entire list region with a single centered block — heading plus one line of body text. No icon required; if one is used, something neutral (an outline shape), never a sad/broken visual. No call-to-action button, since creating a habit isn't part of this slice.

**Copy.**
> No habits yet.
>
> Once a habit is added, its current and longest streaks will appear here.

### Loading
*Flagged in `03-ux.md` as not triggered by this slice's synchronous, in-memory service — included here so a future networked frontend isn't left to invent tone from scratch.*

**Layout.** A plain, generic loading indicator (standard spinner or skeleton rows) replacing the list region — no bespoke flame/streak-themed loading animation, no per-row shimmer shaped like a progress bar.

**Copy.**
> Loading habits…

### Error
*Invalid/unknown habit id, malformed request, or a failed load — a system fault, not a behavioral read-out.*

**Layout.** Deliberately looks like ordinary software error handling — plain text, a neutral system icon if any (a generic caution glyph is acceptable *here specifically*, since this is the one state that should read as distinct from the calm mirror tone, not blended into it). A failed initial load replaces the list region; a failed single action (e.g., a log call that didn't go through) surfaces inline near the control that failed, not a full-screen takeover.

**Copy** — failed list load:
> Something went wrong loading your habits. Try again.

**Copy** — unknown/invalid habit id:
> This habit couldn't be found.

**Copy** — failed log action (inline):
> That didn't go through. Try again.

## 3. Final copy set

All user-facing strings in one place. `{habit}`, `{n}`, `{m}`, `{date}` are the only templated values; everything else ships verbatim.

| Purpose | String |
|---|---|
| Current-streak label | Current streak |
| Longest-streak label | Longest streak |
| Log control (default) | Log today |
| Log control (already logged today) | Logged |
| Not-started status | Not started yet. Log today to begin. |
| Healthy status / confirmation after logging | Logged today. |
| At-risk status (detail) | Logged yesterday. Not yet today. |
| At-risk tag (list) | Not yet today |
| Broken status (detail) | Not logged yesterday. Today starts a new streak. |
| Broken tag (list) | New streak |
| Last-logged metadata | Last logged {date} |
| Empty heading | No habits yet. |
| Empty body | Once a habit is added, its current and longest streaks will appear here. |
| Loading | Loading habits… |
| Error — list load failed | Something went wrong loading your habits. Try again. |
| Error — habit not found | This habit couldn't be found. |
| Error — log action failed | That didn't go through. Try again. |

**Copy rules.**
- "Longest," never "best" — "best" implies competition against yourself, which is exactly the framing this product refuses.
- Pluralize the unit correctly at streak length 1 ("1 day," not "1 days") — a 1-day streak gets the same calm, un-broken-looking treatment as any other length, down to the grammar.
- "Broken" is never printed; it's an internal name for the state, not a word the user sees.
- No exclamation points anywhere in this table.

## 4. Interaction notes

**Focus order.** Within a habit row, the only interactive element is the log-today control; habit name and both streak figures are static text, not focus stops (unless the future frontend makes the row itself a link into detail view, in which case the name becomes one additional stop, immediately before the log control). Tab order moves straight down the list, one stop per row.

**Keyboard.** The log-today control is a real button — operable via Enter or Space, no hover-only or press-and-hold-to-confirm gesture (press-and-hold is itself a small gamified friction pattern, ruled out on tone grounds as much as access grounds, per `03-ux.md` §5). After logging, focus stays on the same control; nothing steals focus to a toast, modal, or animation.

**Logging is idempotent, visibly.** A second tap on an already-logged-today habit is a no-op against the data and should be a no-op on screen too — the control's "Logged" label doesn't re-trigger a confirmation, and no live region re-announces. Nothing about the interaction should look like a correction, because the user didn't do anything wrong.

**No gamifying motion — a hard constraint, not a style preference.** No count-up animation on any numeral (streak numbers just render the new digit). No confetti, celebration, or success animation on logging. No progress-bar fill toward a goal. No flame or icon that grows with streak length. No shake, pulse, or attention animation on at-risk. No shatter, break, or decay animation on broken. State changes are immediate and static — a number or tag simply reads differently after the underlying data changes, the same way it would on a page refresh.

**Screen-reader phrasing.** Every habit's accessible name follows one fixed field order — name, current streak, longest streak, then the state fact — so a screen-reader user scanning the list hears a predictable pattern regardless of which state a given habit is in:

- Not started: *"{habit}. Current streak 0 days. Longest streak 0 days. Not started yet."*
- Healthy: *"{habit}. Current streak {n} days. Longest streak {m} days. Logged today."*
- At-risk: *"{habit}. Current streak {n} days. Longest streak {m} days. Logged yesterday; not yet logged today."*
- Broken: *"{habit}. Current streak 0 days. Longest streak {m} days. Not logged yesterday; today starts a new streak."*

Streak counts are always exposed as this plain text — never encoded only in an icon, flame glyph, or color. If a live region announces `atRisk` clearing right after a log, it fires exactly once, flatly: *"{habit} logged for today. Current streak {n} days."* — not a repeating alert, not framed as an achievement.

## 5. Component vocabulary (new — greenfield)

The minimal set this slice introduces. Nothing here is a design system; it's just enough to build these states.

- **HabitRow** — one habit's line in the list view: name, current streak, optional state tag, longest streak, log control.
- **StreakFigure** — a labeled number (label + numeral + unit), reused for both current and longest streak in both list and detail — the two are differentiated by label text and type scale only, never by color, so there's no implicit "good number / bad number" coding.
- **StateTag** — the small text label used for both at-risk ("Not yet today") and broken ("New streak"). Deliberately one shared component, not two, so the two states are structurally forced to share the same restrained visual family — plain text weight, neutral ink color, no red/orange/amber, no icon badge, no border that reads as a warning chip. It must be tonally indistinguishable, at a glance, from an ordinary metadata label like a date.
- **LogTodayControl** — the actionable log-completion element. A real button; label swaps between "Log today" and "Logged." No hover-only or hold-to-confirm variant exists.
- **EmptyState** — full-region heading + body used for "no habits yet."
- **HabitDetail** — composes one habit's name, both StreakFigures, an optional StateTag, the last-logged line, and a LogTodayControl into the single-habit view.
- **ErrorNotice** — neutral, technical-toned text; renders full-region for a failed list load, or inline near a control for a failed single action.

No dedicated component is defined for Loading: that state is speculative for this slice (the service is synchronous and returns no loading state today), so it's left to whatever generic/standard loading primitive the future frontend already has, rather than designing bespoke chrome for a state nothing in this slice triggers.
