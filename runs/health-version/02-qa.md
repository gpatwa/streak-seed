## Version read once at startup

src/server.js:15-17: `const VERSION = JSON.parse(readFileSync(new URL("../package.json", import.meta.url), "utf8")).version;`
is a module-level constant evaluated at import. The handler (line 298) only references `VERSION`; no `readFileSync`
or `package.json` access in `handleRequest`. Verified by inspection. Not behaviourally tested (see Observations).
Side effect, harmless: the module now fails at import if `package.json` is missing/unparseable, consistent with the
existing import-time asset read at line ~56-60 that `npm run build` already relies on; `build ok` confirms it loads.

## Scrutiny of the two relaxed tests

Diff scope: exactly 3 files. `src/server.js` (+7/-1: the constant, the field), `test/server.test.js` (S1 relaxed,
S1b added), `test/client-server.test.js` (C19 line 136 relaxed). Nothing else: no client, dependency, `.agentic`, `.claude`,
bind or route change. The only untracked items are `runs/` artefacts.

- **S1** asserted `deepEqual(body, {status:"ok"})`. The intended contract change makes that assertion false by definition,
  so some edit was unavoidable. Relaxing to `status === "ok"` while S1b adds strictly stronger whole-body equality
  (including "no extra keys" and the exact version) in the same file means net coverage of `/health` in server.test.js
  went up, not down. Test is still named for "no X-User-Id required" and still sends none. Judgement: minimal and correct.
- **C19** asserted the same old whole body, and fails with the new contract (the implementer reports hitting this
  at 91/92). It is outside the planned files, but it is a necessary edit, not scope creep: leaving it red would fail
  `qa:mvp` and the intent's "every existing test" has to be read as "every existing test that does not assert the
  superseded body". C19's stated purpose is "unaffected by the static route" (a routing-regression check), and 200 +
  `status:"ok"` still tests that. Judgement: necessary and does not weaken what C19 is for. Exact-body coverage is
  held by S1b only at the server.test.js harness, not through the client-server harness (same `createStreakServer`, so
  no real gap).
- Neither relaxation can mask a wrong or missing `version`; S1b alone does that, and it was shown to fail without the fix.
